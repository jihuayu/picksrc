## Reuse decisions

- `react-grab/primitives`: not imported. The pinned source entry imports animation freezing, global-interaction freezing and update-freezing helpers alongside picking context. That is enough to rule out importing the full entry as the framework-neutral core; a separate tree-shaken weight/side-effect harness for subpath candidates remains outstanding. The SDK's base picker is implemented locally with `composedPath` and WeakMap IDs.
- v-comment: searched available Codex workspace documents for `selection.ts` and `dom-resolution.ts`; neither was accessible. No code was copied and migration compatibility is not claimed.
- Vue: after requesting the permitted network execution approval, official Vue 3.5.44 `@vue/compiler-sfc` and `@vue/compiler-dom` plus `@vitejs/plugin-vue` 6.0.10 were installed and locked. `compileTemplate`'s official `nodeTransforms` extension was exercised and a Vite dev server transform was inspected. It emits an opaque ID for every source AST element and a separate component-callsite role for Vue component nodes. The adapter matches each compiler location's exact `loc.source` slice against the original `.vue` file, compensating for the compiler's full-SFC versus template-block offset behavior. It returns exact range records and reads only the verified node source range after checking full-file SHA-256, build/scope identity, project root, range and size. Production Vite output was minified with esbuild; the opaque markers survived, no development location hint was emitted, and the absolute project path was absent from the production JS fixture. Source-map mapping is not used for the direct AST position; source map evidence remains a separate future resolver.
- React: official `babel-plugin-react-compiler` entrypoints expose Babel AST compiler modules and option schemas, so the plausible reuse path is an opt-in Babel transform. No custom visitor, marker survival, source-map composition, or React runtime association was tested; React remains unsupported.
- Solid: official `babel-preset-solid` 1.9.16 delegates JSX lowering to `babel-plugin-jsx-dom-expressions` with preset options. This establishes a compiler-stage integration point but no node-identity path. No transform-order, compressed fixture, or runtime-owner proof was performed; Solid remains unsupported.
